# Публикация Литоры

## Используемый способ

Сайт публикуется из ветки `gh-pages`. Репозиторий `main` содержит исходники, тесты и принятые материалы. Дополнительное OAuth-разрешение `workflow` не требуется.

```sh
npm run publish:pages
```

Команда требует чистой сохранённой истории `main`. Она запускает `npm run check` (логику и Playwright), собирает сайт с правильным базовым путём, затем отправляет только содержимое `dist/` в `gh-pages`. Ошибка проверки останавливает публикацию. История ветки сохраняется, force push не используется.

В Settings → Pages источник должен быть **Deploy from a branch**, ветка `gh-pages`, папка `/`.

## Обычное обновление

Сохранить изменения коммитом, отправить `main`, затем запустить `npm run publish:pages`. Простой push в `main` сам по себе не обновляет публичный сайт.

## Откат

Создать `git revert` для неудачного коммита в `main`, отправить его и повторить `npm run publish:pages`. После проверки Pages получит предыдущий вариант. Не применять force push для отката публичной истории.

## Проверка опубликованного адреса

```sh
PLAYWRIGHT_BASE_URL=https://vladnes7.github.io/litora-resort/ npm run test:e2e
```

При этом временный локальный сервер не запускается. Конечный `/` обязателен, чтобы относительные пути разрешались внутри проекта.

## Неактивный пример workflow

`templates/pages-workflow.yml.example` содержит вариант автоматического выпуска через Actions. Он не активирован: текущее OAuth-подключение GitHub не разрешает создание workflow. Этот пример не требуется для рабочего способа публикации из `gh-pages`.

Формы остаются демонстрационными. Публикация не подключает оплату, рассылки или обработку персональных данных.
